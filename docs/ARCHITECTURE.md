# Native integration

Lua performs game-thread reflection and screen binding. In the menus, and while the CRTV is down with nothing playing or fading, it reads the game in full ten times a second and between only asks whether the CRTV came up (`radioUp`), so idle frames cost two calls and raising is still noticed on the next frame. It creates four transient/rooted media objects in the MediaAssets class's loaded package and a bounded pool of unregistered component keys for station markers. Named objects survive Lua reloads. A 96-byte input packet supplies validated media, radio, world and texture addresses; a 56-byte status packet returns selection, rendering, timing and audio state. A separate 528-byte setup packet supplies at most 64 private marker keys.

The real screen material is obtained through `radio.RadarPropMap[radio.PlayerCharacterType].RadarTexture`, with its widget checked against `GetCRTVWidget()`. Ownership tracking restores the original texture only while the mod still owns the parameter. Invalidated objects are discarded. A game-side overwrite is preserved.

The renderer reads the original texture's RHI dimensions/format through PDB-verified APIs and layouts. Its configured output defaults to 640x480 in the original RGBA8/BGRA8 format. Letterboxing is calculated in original texture coordinates and scaled into the output, retaining normalized screen UV placement. Native Kismet canvas begin/draw/end calls submit engine-managed render work. Only changed media timestamps/aspect/layouts redraw.

Dial markers use `UCRTVTuningDisplayWidget::UpdateDisplayedSignal` and `RemoveDisplayedSignal`. Private unregistered component keys never become world radio sources. Markers retain native size, baseline and X-frequency mapping; only their brush tint becomes magenta (`UImage::SetBrushTintColor`, which the game sets to the signal kind's colour; an image colour would multiply with it). UI capacity is extended by available station count, then restored while still owned. Invalidated weak pointers are never dereferenced. Native tuning controls are not changed, except quick tuning: `UHandheldRadioComponent::DoRadioQuickTune` (Q/E, the D-pad) jumps to the next game signal among the level's sources, which the stations are not, so a MinHook detour runs it and then, when an enabled station lies nearer that way (`tf_quick_tune`), sets that frequency as the game does (`SetTunedFrequency_Internal(frequency, true, false)`, then `UCRTVWidget::QuickTuneJump`). The detour is installed once a fitting profile is there.

The same marks go to Townfall Companion's phone dial, which draws the game's signals from their sources and never sees the game's dial: whenever the stations change (setup, reassignment), the DLL rewrites `%TEMP%\townfall-companion-dial-marks.txt` whole, a line `TFMARKS1 <count>`, then `<frequency> <r> <g> <b>` a mark in the marker tint (`MARK_TINT`, linear RGB). The Companion reads it once a second; without the Companion the file is unused.

Lua publishes validated placed-source intervals from the current world, including late enemy sources, in a bounded revision packet (32-byte header with the level's most common waypoint tuning range, up to 256 double pairs). Unless `stations.ini` sets a tolerance, the stations take that range (tolerance + hysteresis), so they tune like the game's own videos; 0.010 applies while a level has no waypoints. The native reader checks epoch, revision and interval validity, with a 250 ms refresh. Automatic assignments exclude each game's reserved interval plus the custom station's tolerance/hysteresis. Auto mode tries keeping the group at its current end, then the other end. Manual pins and file indices remain stable. Frequency changes close active playback, preserve its file bookmark, update only private markers, and save enabled assignments. Unknown world data disables automatic stations until validated ranges arrive.

Selection uses the same tolerance+hysteresis radius for entry, hold and reentry, with a 1e-7 rounding allowance for float32 game frequencies. Assignment spacing and excluded game ranges include that allowance. A one-millihertz grid fits end groups without including zero or one in their matching ranges. Reentering the current station during its short fade cancels the fade without closing/reopening the decoder. Fully disconnected stations still reopen at their bookmarks.

Electra implements file opening, rate, looping, close, preparation and time queries. MSVC time-return methods use the verified hidden-result ABI. The player facade's native Seek receives a pointer to an eight-byte FTimespan. Each file's bookmark is captured before close. Reopening submits a seek and keeps picture/audio unbound while `FMediaPlayerFacade::IsSeeking` reports pending, bounded by the normal open timeout. A positive time is required after completion; an exact-time window is avoided because playback can already have advanced. No automatic retuning occurs.

Electra's Matroska reader takes only the audio codecs in its table: AAC, Opus, FLAC and MPEG audio (`A_AAC`, `A_OPUS`, `A_FLAC`, `A_MPEG/L1`-`L3`; no `A_AC3`, `A_EAC3` or `A_DTS` exists in the game). Other audio tracks are left out and the picture plays silently, so discovery reads each MKV's first 64 KB (`tf_mkv_audio`: EBML Segment, Tracks, TrackEntry type and CodecID) and logs `No sound from` when it has audio tracks but none the reader takes. A head that is cut off or has no tracks says nothing.

Audio uses one unregistered MediaSoundComponent and one strong native generator reference. Its active bit permits native queue attachment without a second Unreal audio-device consumer. OnEndGenerate clears the queue, so every successful open obtains a fresh generator. A shared lock prevents concurrent release; callbacks skip contended swaps. Audio threads never access game UObjects.

The game's FMOD runtime system is obtained without hooks. C exports come from already-loaded FMOD 2.03 libraries. A tail DSP injects stereo PCM before effects/faders, permitting generation on an otherwise silent bus. An already-held bus lock is borrowed on result 78; cleanup unlocks only owned locks and shared group identity is checked before use. Windows fallback uses MMCSS Audio scheduling, four ordered 20 ms buffers and device reset on enable/disable. A 250 ms heartbeat stops audio after callbacks cease.

UObject calls stay on the game thread. Explicit shutdown closes media/audio resources; no engine calls or thread waits occur under the DLL loader lock.

The engine functions and layouts come from the game profile, `Scripts/tf_video.profile` (`TfProfile` in `native/profile.h`: the game's build stamp, image size and PDB identity, each function's RVA and first 16 bytes, and 30 offsets and enum values), which `profile.h` lists by name with each function's expected signature. Before any engine call the DLL checks it against the running image: timestamp, image size, PDB identity and the first 16 bytes of every called function. If it doesn't fit (a game update, or a first start without one), the DLL runs its own `tf_video_profile` entry (`native/game_profile.c`) once per game run through System32's `rundll32.exe`, in a process of its own, below normal priority and without a window, and keeps engine calls off meanwhile (status error 7). That process reads the game's PDB through System32's dbghelp.dll, apart from the game because dbghelp takes about 1.7 GB for this PDB for the few seconds it needs. It looks every function up and compares its signature, checks each member's size, the enum values and the layouts the DLL declares itself, and writes the profile whole (staged, then renamed) or not at all, appending its outcome to `tf-video.log`; exit code 2 means the update changed something the DLL relies on, 3 that a file couldn't be read. `tf_video_info` notices the process's end, takes the new profile and enables the stations in the same session (`tf_reassign_automatic`, `publish_marks`). The Lua side keeps its bridge open meanwhile and asks `tf_video_info` once a second; on a final error (1, or 2 for `stations.ini`) its loop ends for that game run. The release ships the profile of the build it was tested on, so a fresh install reads no PDB. `tests/expected_profile.json` is that profile, which `game_profile.c` must reproduce exactly for that build.

Each game start moves `tf-video.log` to `tf-video.previous.log` and begins a new one.
